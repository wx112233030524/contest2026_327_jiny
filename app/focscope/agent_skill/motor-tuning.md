# FOC 电机整定
整定 FOC 电流环/速度环 PI 参数。触发词：整定、调参、PI、电流环、速度环、电机调不好。

## When to use

用户要求整定或调整电机参数时，例如：

- "帮我整定一下这台电机"
- "电流环参数调一下"
- "电机抖得厉害，重新整定一下"

不适用：电机不转/报错等硬件故障排查（那应该先看 `focscope` 的波形和 CAN 链路状态）。

## How to use

1. **确认电机参数。** 用户没说就按默认值，并在回复里说明用了默认值：
   `Rs=0.5` `Ld=0.001` `Ke=0.01` `poles=4`
2. **判断用途。** `0`=云台（低带宽、高稳定）；`1`=航模（高响应）；`2`=机器人关节（平衡）。
   用户没说就用 `2`。
3. **用 `run_shell` 跑一次整定**（参数顺序固定，`Lq` 自动等于 `Ld`）：

   ```text
   ai_tuner_test <Rs> <Ld> <Ke> <poles> <usage>
   ```

   例如默认值 + 机器人关节：

   ```text
   ai_tuner_test 0.5 0.001 0.01 4 2
   ```

4. **用 `read_file` 读结果**：`/data/agent/tune_result.json`。

5. **按 `status` 字段决定怎么回复：**

   - `ok` → 汇报 6 个 PI 参数（电流环 `Kp_Id`/`Ki_Id`/`Kp_Iq`/`Ki_Iq`，速度环 `Kp_Speed`/`Ki_Speed`）。**只有电流环 4 个过了白名单**，速度环是模型按 1/10 降阶推的
   - `whitelist_fail` → 说明 AI 给出的电流环参数超出理论值 ±50% 区间、已被安全机制拒绝，
     **电机保持原参数未被改动**
   - `parse_fail` → AI 返回内容无法解析，建议重试
   - `http_fail` / `http_code_fail` → AI 调用失败，检查网络连接
   - `no_key` → 未配置 MiMo API key，提示用户在 `foc_ai_tuner.c` 填入后重新编译

6. **回复必须包含**：6 个参数值、用途模式、电流环是否通过白名单校验。

## Example

```text
User: "帮我整定这台电机，是个云台用的"
→ run_shell: ai_tuner_test 0.5 0.001 0.01 4 0
→ read_file: /data/agent/tune_result.json
→ "整定完成（云台模式）。电流环 Kp_Id=0.006702 Ki_Id=3351.03（已过白名单校验），
   速度环 Kp_Speed=0.000670 Ki_Speed=335.10。"
```

```text
User: "重新整定一下"
→ run_shell: ai_tuner_test 0.5 0.001 0.01 4 2
→ status=whitelist_fail
→ "AI 给出的 Kp_Id 超出理论值 ±50% 区间，已被白名单拒绝，电机参数保持原样。
   可以再试一次。"
```

## 安全说明

白名单只校验电流环 4 个参数：超出理论值 ±50% 即拒绝，电机保持原参数，不让模型的
错误变成电机的危险参数。速度环 2 个参数**没有这层校验**，只是提示词要求模型按
1/10 降阶推算，所以不要对外宣称"速度环也校验过"。

因此：**被拒绝的参数绝不能描述成"已生效"**；**没校验过的也要说清是没校验的**。
